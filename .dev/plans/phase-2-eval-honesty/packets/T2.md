### Step 3 — Create `tests/eval/golden_set/test_runner_unit.py`

The file must be plain pytest (no golden-set fixtures, no `mark=golden`, no `--golden-tier` dependency).

Minimum required tests:
1. `test_run_retrieval_check_passes_with_keywords` — build a minimal `GoldenCase` with `requires_multi_hop=True` and a `retrieved_context` containing matching keywords; assert `outcome.passed is True`.
2. `test_run_retrieval_check_fails_empty_context` — same case with `retrieved_context=""` (or missing components); assert `outcome.passed is False`.
3. `test_run_retrieval_check_requires_multi_hop_does_not_affect_outcome` — demonstrate that `requires_multi_hop=True` vs `False` produces identical `passed` values for the same context (confirms sub-check removal is correct).
4. `test_run_replay_check_passes_with_inline_fixture` — build a minimal `GoldenCase` with `expect.replay` and a hand-authored `ReplayFixture` object (not from disk); patch/monkeypatch `load_replay_fixture` to return it; assert `outcome.passed is True`.

The replay test must use the §2-binding `response` dict keys: `answer`, `retrieval_strategy`, `sources`, `trace`.

### Step 4 — Write decision log

Create `.dev/decision-logs/` directory if absent, then write `.dev/decision-logs/T2-requires-multi-hop.md`. Required sections:
- **Decision**: Remove `sub["multi_hop_declared"]` always-pass stub from `run_retrieval_check`.
- **Context**: Field `requires_multi_hop: bool` in `ExpectRetrieval`; runner.py lines 198–199 set `sub["multi_hop_declared"] = True` unconditionally when flag is true, adding a sub-check that always passes and contributes no signal.
- **Alternatives rejected**: (1) Implement real multi-hop validation using trace/graph inputs — no data source exists in retrieval YAML input; would require architectural changes out of scope for Phase 2. - **Chosen approach**: Remove stub only. Field retained in schema as documentation of multi-hop intent; no validator added. Deferred: if trace data is added to retrieval YAML input in a future phase, a real hop-count check can be implemented.
- **Deferred items**: Real `requires_multi_hop` validation (blocked on trace/graph data in retrieval input).
