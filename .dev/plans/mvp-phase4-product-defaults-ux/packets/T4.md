**Inputs:** T1 must have completed. The env isolation requirement (`env={"ARIA_PLACEHOLDER_API": "true"}`) is necessary precisely because T1 flipped the default to `"false"`. If T4 ran before T1 without explicit env isolation, it would have passed vacuously on the old `"true"` default; post-T1, it would attempt a live backend connection and fail.

**Outputs:**

**Kill criteria:**
1. Halt if `runner.invoke(app, ["query", "test question", "--json"], env={"ARIA_PLACEHOLDER_API": "true"})` raises an exception, connects to a backend, or exits non-zero — report the full exception/output and await investigation. Do not weaken the invocation to make the test pass.
2. Halt if parsing `result.stdout` as JSON raises a `json.JSONDecodeError` — the `--json` path must produce valid JSON; if it does not, that is a pre-existing code defect, not a test defect. Report without masking.
3. Halt if the JSON output does not contain all five expected keys (`answer`, `sources`, `retrieval_strategy`, `trace`, `aria_mode`) — do not reduce the assertion set to make the test pass.
4. Halt if T1 has not landed (read `api/config.py` line 10 and confirm it reads `"false"` before writing the test).
5. Halt if adding this test causes any pre-existing `test_cli_entry.py` test to fail.

**Log tier:** `standard`

**Risks & mitigations:**
- *Risk:* `CliRunner.invoke env=` does not propagate to `os.environ` for `os.getenv` calls — Click's CliRunner patches `os.environ` during invocation, and `load_dotenv()` in `aria/cli/main.py` runs with `override=False` (default) so it cannot clobber the CliRunner-set value; if this chain breaks, kill criterion (1) fires.
- *Risk:* `AppConnections()` constructor has side effects when instantiated without args — pre-existing help tests import the same `app` without triggering this; kill criterion (1) catches regressions.
- *Risk:* `result.stdout` contains leading log lines before the JSON — strip and parse only the last JSON block, or assert that `result.stdout.strip()` is valid JSON. Use `json.loads(result.stdout)` directly first; if that fails, check for extra output with `print(result.stdout)` in the kill criterion report.

```python
"""Smoke tests for the ``aria`` Typer CLI (no live backends)."""

from __future__ import annotations

from typer.testing import CliRunner

from aria.cli.main import app

runner = CliRunner()


def test_root_help_exits_zero() -> None:
    result = runner.invoke(app, ["--help"])
    assert result.exit_code == 0
    assert "ARIA" in result.stdout


def test_query_help_lists_options() -> None:
    result = runner.invoke(app, ["query", "--help"])
    assert result.exit_code == 0
    assert "--regulation-id" in result.stdout or "-r" in result.stdout
```

**Suggested new test (append after `test_query_help_lists_options`):**

```python
def test_query_json_placeholder_returns_valid_payload() -> None:
    result = runner.invoke(
        app,
        ["query", "test question", "--json"],
        env={"ARIA_PLACEHOLDER_API": "true"},
    )
    assert result.exit_code == 0, f"Expected exit 0, got {result.exit_code}:\n{result.output}"
    import json
    payload = json.loads(result.stdout)
    assert "answer" in payload
    assert "sources" in payload
    assert "retrieval_strategy" in payload
    assert "trace" in payload
    assert payload["aria_mode"] == "placeholder"
```

Notes on the suggested implementation:
- Import `json` inline or at the module top — either is acceptable; inline avoids polluting the module namespace for a single test.
- `result.output` (not `result.stdout`) includes stderr in Typer's CliRunner; use `result.stdout` for JSON parsing to avoid stderr contamination.
- Do not use `result.output` for `json.loads` if the app emits any stderr lines before the JSON.
- The `env=` dict passed to `runner.invoke` is merged with the existing environment; no other env keys need to be set for placeholder mode.
