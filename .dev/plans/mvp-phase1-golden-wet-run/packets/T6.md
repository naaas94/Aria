## §1 Task statement (verbatim)

Phase 1 of the Aria MVP is a one-session golden-path wet run that proves the end-to-end live stack operates correctly. The session exercises the full Phase 1 command sequence — `docker compose up -d neo4j chromadb`, `ARIA_PLACEHOLDER_API=false`, then `aria init` → `aria ingest <sample>` → `aria query` → `aria impact <id>` → `aria telemetry` → optional `aria serve` + curl → `pytest tests/integration -m integration` — records every failure inline in `.dev/MVP_PICKUP.md`'s wet run log, applies minimal targeted fixes for each blocker, and concludes with a signed-off confirmation that `aria ingest` preflight (Neo4j + Chroma + LLM all required) is strictly more demanding than `/ready` (LLM optional).

**Non-goals:** Phases 2–6; HTTP-level ingest; comprehensive CliRunner test suites; refactoring beyond minimal Phase 1 blockers; production hardening; scratch orchestration layer changes.

- T5 complete: `aria status` shows preflight/LLM asymmetry note.

**Outputs:**
1. `.dev/MVP_PICKUP.md` wet run log — all fields filled:
   - Date, environment (OS, Python version, LLM model + endpoint, Neo4j/Chroma versions)
   - `ARIA_PLACEHOLDER_API=false` confirmed

   - Failures / surprises (inline, with fix refs)
   - Fixes applied (commit SHAs or "no fix needed")
   - Sign-off: `MVP golden path OK? Y/N`
2. `.dev/decision-logs/T6-wet-run.md` — architectural log including:
   - Environment details
   - Alternatives considered (e.g. seed_corpus vs aria ingest, fallback to placeholder mode)
   - Decisions made and rationale
   - Preflight vs readiness assertion with evidence
   - Deferred items (e.g. Flag 6 CLI tests)
3. Inline fix commits (if any), referenced by SHA in wet run log.

**Kill criteria:**
- (a) Halt and record in wet run log if `docker compose up -d neo4j chromadb` services are not healthy within 60 s. Document the error and environment.
- (b) Halt and record if `aria init` raises an unhandled Python exception (not a user-facing error message). Fix before continuing.
- (c) Halt and record if `aria ingest` LLM preflight never resolves after 120 s total (probe_llm_reachable has 12 s timeout internally; operator waiting > 120 s indicates LLM env misconfiguration). Fix LLM config or document as environment blocker.
- (d) Halt and record if `aria query` raises an unhandled Python exception — this is a structural bug, not a data gap. Fix before continuing.
- (e) If any inline fix requires touching > 3 files outside the §2 file list, halt, document the finding in the wet run log, and flag for re-plan.
- (f) Do not run `pytest tests/integration -m integration` until T2 is confirmed complete (check that the command collects ≥ 1 test with `--collect-only` before running).

**Log tier:** architectural

**Risks & mitigations:**

1. **LLM timeout** — `probe_llm_reachable` uses 12 s timeout; if LLM is unreachable, `aria ingest` exits 1 with `"  missing: llm: ..."`. Mitigation: before starting, verify `LLM_*` env vars are set (or Ollama is running); document the LLM endpoint in the wet run log header. If LLM is unavailable, document it as an environment blocker; do not use `ARIA_PLACEHOLDER_API=true` as the golden path — it bypasses the live stack.

2. **Do NOT use `scripts/seed_corpus.py` as the primary ingest path** — it calls `ingest_document` without `build_full_ingest_wiring`, skipping entity extraction, graph write, and vector index. Using it leaves `aria query` and `aria impact` ungrounded. Use `aria ingest tests/fixtures/sample_regulation.html` instead. (Flag 4 coupling, confirmed.)

3. **Regulation ID for `aria impact`** — Use the IDs printed by `aria ingest` (T4 output), not the `seed_graph.py` hard-coded IDs (`reg-gdpr`, `reg-eu-ai-act`). If T4 printed `(none — Regulation nodes not found)`, either: (a) re-run ingest with `--force` to try again, (b) run `python scripts/seed_graph.py` to populate known IDs and use `reg-gdpr`, or (c) document the gap and continue.

4. **Preflight vs readiness assertion** — To confirm the asymmetry: with LLM unreachable, run `aria ingest tests/fixtures/sample_regulation.html` (should exit 1, print `"  missing: llm: ..."`) and then `aria serve --port 8081 &; sleep 2; curl http://127.0.0.1:8081/ready` (should return 200 with `"llm_ok": false`). Record both outputs in the wet run log as the formal assertion.

5. **`aria status` vs `aria ingest` gate** — After running `aria status`, read the T5 note confirming LLM is optional for status. Verify by checking the exit code when LLM is down: `aria status` exits 0, `aria ingest` exits 1.
