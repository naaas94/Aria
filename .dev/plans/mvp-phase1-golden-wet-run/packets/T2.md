## §1 Task statement (verbatim)

Phase 1 of the Aria MVP is a one-session golden-path wet run that proves the end-to-end live stack operates correctly. The session exercises the full Phase 1 command sequence — `docker compose up -d neo4j chromadb`, `ARIA_PLACEHOLDER_API=false`, then `aria init` → `aria ingest <sample>` → `aria query` → `aria impact <id>` → `aria telemetry` → optional `aria serve` + curl → `pytest tests/integration -m integration` — records every failure inline in `.dev/MVP_PICKUP.md`'s wet run log, applies minimal targeted fixes for each blocker, and concludes with a signed-off confirmation that `aria ingest` preflight (Neo4j + Chroma + LLM all required) is strictly more demanding than `/ready` (LLM optional).

**Non-goals:** Phases 2–6; HTTP-level ingest; comprehensive CliRunner test suites; refactoring beyond minimal Phase 1 blockers; production hardening; scratch orchestration layer changes.

## §4 Subtask spec — T2

**Scope:** Apply `@pytest.mark.integration` at the class or module level in `tests/integration/test_end_to_end.py` and `tests/integration/test_ingestion_pipeline.py`. Update `pyproject.toml` marker description to reflect that the `integration` marker covers both infrastructure-requiring and infrastructure-free tests. Resolves Flag 1 (context map).

**Files to touch:**
- `tests/integration/test_end_to_end.py` — add `@pytest.mark.integration` to test classes
- `tests/integration/test_ingestion_pipeline.py` — add `@pytest.mark.integration` to test classes
- `pyproject.toml` — update marker description

**Contract bindings:** Tests contract: marker name `integration`, command `pytest tests/integration -m integration` collects ≥ 1 test and passes.

**Inputs:** None.

**Outputs:**
- `tests/integration/test_end_to_end.py` with `@pytest.mark.integration` applied to `TestAPIEndpoints`, `TestContractToGraphFlow`, `TestOrchestrationFlow` classes.
- `tests/integration/test_ingestion_pipeline.py` with `@pytest.mark.integration` applied to `TestHTMLParsing`, `TestChunking`, `TestIngestionPipeline`, `TestNeo4jIngestionDedup` classes.
- `pyproject.toml` with updated marker description from `"requires running Neo4j and ChromaDB"` to `"integration-level tests; subset requires running Neo4j and ChromaDB"`.
- Changelog entry.

**Kill criteria:**
- (a) Halt if `pytest tests/integration -m integration` fails after applying markers — the tests themselves must pass before T2 is complete. Fix any test failures before marking done.
- (b) Halt if context-map flag 1 is unresolved at execution start.

**Log tier:** standard

**Risks & mitigations:**
- **CI dry-run coverage reduction (§5.4 confirmed coupling):** Existing CI may run `pytest -m "not integration"` to exclude live-infra tests. After T2, `tests/integration/` tests (which don't actually need live infra) will also be excluded from those runs, silently reducing coverage. Mitigation: update the `pyproject.toml` marker description AND note this risk in the changelog. Do not change any CI workflow files (out of scope for Phase 1).
- **scratch orchestration import in test_end_to_end.py:** `test_end_to_end.py` imports `aria.orchestration.scratch.graph` and `aria.orchestration.scratch.state`. These modules are in the excluded Phase 1 scope but should be importable. Run `pytest --collect-only tests/integration/` first to confirm collection succeeds before applying markers.
