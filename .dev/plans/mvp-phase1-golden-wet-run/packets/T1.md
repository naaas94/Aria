**Non-goals:** Phases 2–6; HTTP-level ingest; comprehensive CliRunner test suites; refactoring beyond minimal Phase 1 blockers; production hardening; scratch orchestration layer changes.

## §4 Subtask spec — T1

**Scope:** Add a committed sample HTML regulatory document (`tests/fixtures/sample_regulation.html`) that `aria ingest` can consume during the wet run. Resolves Flag 2 (no committed ingest sample in repo).

**Files to touch:**
- `tests/fixtures/sample_regulation.html` (create)

**Contract bindings:** Naming (path frozen); Types/interfaces (HTML parseable by `aria/ingestion/parsers/html_parser.py`).

**Inputs:** None.

**Outputs:** `tests/fixtures/sample_regulation.html` — committed HTML file with:
- A `<title>` tag (used by `html_parser.py` to set `doc.title`)
- At least two headings (`<h1>` or `<h2>`)
- Multi-sentence paragraphs in each section (enough text for chunker to produce ≥ 1 chunk; typically ≥ 3 sentences per section)
- Plausible regulatory prose (AI Act / GDPR style) so entity extraction has something meaningful to extract

**Kill criteria:**
- Halt if inspection of `aria/ingestion/parsers/html_parser.py` reveals it requires a specific HTML structure (e.g. a particular CSS class, `<article>` tag, or custom attribute) that generic `<h1>`/`<p>` HTML does not satisfy. Fix the sample to match the required structure before committing.

**Log tier:** trivial

**Risks & mitigations:**
- Parser may derive `doc.title` from `<title>` tag only. Include `<title>Sample Regulation — AI Systems</title>` in `<head>`.
- Chunker needs minimum text length to produce chunks. Write ≥ 3–4 sentences per paragraph section.
